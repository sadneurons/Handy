# Replacement Dictionaries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the flat word-replacement list into named dictionaries with one hand-chosen active dictionary, selectable from tray, settings, CLI, and per audio-file import.

**Architecture:** `AppSettings` gains `replacement_dictionaries` and `active_dictionary_id`; a one-time migration turns the legacy list into a "Clinical" dictionary. The transcription pipeline takes an explicit `DictionarySelection` so live dictation uses the global choice while file import and headless CLI can override it. Tray, overlay, settings UI and import panel read and set the same two fields through two new Tauri commands.

**Tech Stack:** Rust (Tauri 2, serde, tauri-specta, rusqlite migrations), React/TypeScript (Zustand store, i18next, Tailwind).

**Spec:** `docs/superpowers/specs/2026-10-26-replacement-dictionaries-design.md`

## Global Constraints

- Work on a feature branch off `file-import`; push only to `origin`. Never push to `upstream`.
- `src/bindings.ts` is generated by `bun run tauri dev` (or `cargo test` does not regenerate it); after adding or changing commands, run the dev build once to regenerate, then commit the regenerated file. Remind the user to quit any running Handy first.
- All user-facing strings via i18next in `src/i18n/locales/en/translation.json`; tray strings come from the `tray` block of that file.
- Migration dictionary name is exactly `Clinical`. Transcript header line is exactly `Dictionary: <name>` or `Dictionary: none`.
- CLI flag is `--dictionary <name-or-id>`; resolve exact id first, then case-insensitive name; unknown value logs a warning and changes nothing.
- No coexistence with older binaries is required.
- Rust: `cargo fmt`, `cargo clippy`; no `unwrap` in non-test production paths where an error can occur. Run Rust tests with `cd src-tauri && cargo test <name>`.

## Review Focus

1. A stored `active_dictionary_id` that points at a deleted dictionary: no replacements applied, no panic (Task 1 test).
2. Two dictionaries with the same name and `--dictionary <name>`: exact-id match wins, otherwise first name match (Task 5 test).
3. Deleting the active dictionary from the settings UI: active becomes `None` and the tray and overlay stop showing a name (Task 3 test on command behaviour).
4. CSV import with a header row, quoted commas, and blank lines: header skipped, quoted fields honoured, blanks ignored (Task 8 test).
5. Import with "no replacements" while a global dictionary is active: zero substitutions in that transcript (Task 2 test for `DictionarySelection::None`).
